## 評価の設計(本人が決定。2026-10-22)
- 比較するエンジン: Tesseract(日本語、ローカル)、Bedrock の Claude Haiku 4.5(`au.anthropic.claude-haiku-4-5-20251001-v1:0`)、同 Sonnet 4.6(`au.anthropic.claude-sonnet-4-6`)。両モデルとも temperature 0。
- 推論プロファイル: `au.`。行き先は ap-southeast-2 と ap-southeast-4(`GetInferenceProfile` で確認済み)。テキストだけの試験呼び出しは両モデルとも成功(SCP の拒否なし)。
- 評価データ: 合成処方箋100枚 × 劣化条件3種(原画、傾き、ノイズ)= 300画像。各処方箋は薬剤3行で、各条件300行。
- 正解は、画像を作る側が持つ(OCR の結果から作らない)。
- 1回の評価(runId)は、画像を `runs/<runId>/<split>/` に1回アップロードすることで行う。

## 共通の前提(採点)
- 分母は正解ファイルから作る。結果が無い画像は、全行を不正解として数え、件数を別に報告する。
- 行の対応づけ: 正規化した薬剤名の類似度(difflib)の合計が最大になる組み合わせ。同点なら並び順に近いもの。対応しなかった行は「不足」「余分」として別に数える。
- 項目ごとに、NFKC 正規化と空白除去の後の完全一致で正誤を決める。
- 95% 信頼区間: 処方箋単位のブートストラップ(B=2000、シード 20261024)。誤りのある処方箋が5件未満のときは、処方箋単位の Clopper–Pearson 区間(保守的)。
- 百分位: nearest-rank(小さい方から ceil(q·n) 番目)。

## 副次の評価(合否には使わない)
- **非劣性**: Haiku − Sonnet の対応のある差を、同じ処方箋の再抽出で9セルとも算出する。下限が −0.05 より上なら「非劣性を示せた」と報告する(許容差5pt。本人の決定)。
- **再現性**: temperature 0 でも出力が完全に一致する保証はないため、dev を各エンジン2回実行し、行×項目の完全一致率と、セルごとの正解率の差を報告する。eval の信頼区間に実行ごとのばらつきが含まれないことを、限界として書く。

## 凍結(事前登録)
- プロンプトの調整、effort の決定、maxTokens の決定は、開発用セット(dev、20枚)だけで行う。評価セットを見て調整しない。
- 凍結の対象: プロンプト・推論設定・モデル ID(`promptHash` として各項目に保存)、`score.py`、`drugs.normalize`、両エンジンの `parse_lines`。
- eval は、`PROMPT_VERSION` が `v1-draft` でない、作業ツリーが clean、HEAD にタグがある、のすべてを満たさないと実行できない(`eval_run.check_frozen`)。デプロイした Lambda の CodeSha256 を記録する。
- 結果は上書きしない(DynamoDB への条件付き書き込み)。eval は1回だけ実行する。
